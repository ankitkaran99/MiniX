InputMaskEngine

InputMaskEngine is the pure masking engine that powers the MiniX mask plugin and the vanilla adapter in this repository. The engine does not own the DOM. It accepts the current input value, selection range, and mask definition, then returns a new value and caret position.

Public API

MethodPurpose
new InputMaskEngine(options)Create an engine with custom token definitions.
compile(mask)Compile a literal pattern string or a free-mask config object.
apply(payload)Apply a strict edit operation.
paste(payload)Apply a forgiving multi-character insertion.
accepts(payload)Check whether an edit would be accepted.
backspace(payload)Delete backward using mask semantics.
deleteForward(payload)Delete forward using mask semantics.

Mask Modes

The engine supports two distinct models:

  • Literal masks such as (999) 999-9999 or AAAA-9999, where each token occupies a known slot.
  • Free masks, where allowed character type and maximum length matter more than positional separators.
const engine = new InputMaskEngine();

const phone = engine.compile('(999) 999-9999');
const name = engine.compile({ type: 'free', token: 'S', max: 40 });

Usage Example: Edit Payload

const result = engine.apply({
  value: '(987) ',
  selectionStart: 6,
  selectionEnd: 6,
  input: '6',
  mask: phone
});

console.log(result.value);
// (987) 6

Built-In Token Philosophy

Tokens are tiny rules composed of a test and optional transform. That makes the engine flexible enough for uppercase-only letters, digits, alphanumeric slots, or project-specific symbols without hard-coding every business format into the core.

When a project needs specialized formats, add a token rather than forking the edit logic.

Why It Matters

Separating the engine from the framework integration is a good architectural decision for this repository. MiniX can use it through directives, plain JavaScript pages can use it through the vanilla adapter, and future integrations can reuse the same edit semantics without duplicating mask logic.
