Model And Collection

This module adds a lightweight data-modeling layer to the repository. It is designed to remain compatible with plain JavaScript, MiniX_State, and MiniX store-backed data sources. The goal is ergonomic data access and relations without breaking reactive write-through behavior.

Model

Model represents one record. Subclasses can define defaults() and relations(), then read and write attributes through property-style access and helper methods such as get(), set(), fill(), watch(), raw(), and toJSON().

class User extends Model {
  defaults() {
    return { name: '', profile: null, roles: [] };
  }

  relations() {
    return {
      profile: this.hasOne(Profile),
      roles: this.hasMany(Role)
    };
  }
}

Binding helpers like fromState(), fromStore(), and bind() make the model write through to an existing reactive source instead of silently forking a disconnected copy.

Usage Example: Bound Model

const state = new MiniX_State({
  currentUser: { id: 1, name: 'Ankit' }
});

class User extends Model {}

const user = User.fromState(state, 'currentUser');
user.set('name', 'Asha');

console.log(state.get('currentUser.name'));
// Asha

Collection

Collection wraps an array of model items and preserves model normalization across array operations. It supports mutation helpers like pushModel(), removeById(), updateById(), resetModels(), and read helpers like findById(), pluck(), ids(), and sortBy().

ConcernBehavior
NormalizationIncoming plain objects can be turned into model instances automatically.
SerializationtoArray() and toJSON() produce export-friendly data.
ReactivityCollections can operate against reactive adapters instead of only local arrays.

Usage Example: Collection Helpers

class Todo extends Model {}

const todos = new Collection(Todo);
todos.pushModel({ id: 1, text: 'Write docs' });
todos.pushModel({ id: 2, text: 'Review examples' });

todos.updateById(2, { text: 'Review all examples' });
console.log(todos.findById(2).get('text'));

Intended Usage

  • Use Model when raw nested objects are becoming hard to reason about across multiple components.
  • Use Collection when array operations need identity, helper methods, or relation-aware normalization.
  • Keep models lightweight. They should represent domain shape and write-through behavior, not large service layers.
