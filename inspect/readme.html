Inspect.js

Inspect.js is the validation engine used directly by the MiniX form plugin, but it is written as a standalone form and data validator. The library accepts rule definitions, can parse a form into a normalized payload, validates either DOM-based or raw object data, and centralizes how errors are rendered.

Primary API

MethodPurpose
new Inspect(options)Create a validator with custom messages and error-rendering behavior.
init(container, rules)Bind rules to a form container and return the public method bundle.
parseFormData()Extract named fields, including grouped and array-like inputs.
validate()Validate the current form and optionally render errors.
validateData(data)Validate a plain object without DOM coupling.
clearErrors()Remove rendered validation feedback.

Rule Format

{
  field: 'email',
  pretty: 'Email',
  rules: { required: true, email: true, maxlen: 100 },
  messages: { required: 'Email is mandatory.' }
}

The engine keeps rule definitions declarative and applies messages by placeholder substitution. {0} maps to the current rule parameter and {1} maps to the field label.

Usage Example

const inspect = new Inspect().init(formEl, [
  { field: 'email', pretty: 'Email', rules: { required: true, email: true } },
  { field: 'skills[]', pretty: 'Skills', rules: { min_eq_elem: 1 } }
]);

const result = await inspect.validate();
if (result.valid) {
  console.log(result.data);
}

Validator Surface

Inspect.validators contains the built-in rule set. It covers presence checks, string lengths, numeric ranges, equality, array cardinality, regex matching, URLs, email, phone, dates, times, file type and size validation, and several country-specific rules such as PIN code, PAN card, and Aadhaar validation.

Because validators are kept on a static object, the library can be extended by registering additional validator functions for project-specific rules.

Design Notes

  • Empty values short-circuit most validators except required.
  • Form parsing is centralized, so field grouping behavior is consistent across validation runs.
  • Error rendering is configurable through errorHandler, making the library usable outside Bootstrap-style markup.
